# Определение автоматизированного трафика Авито

Проект для отбора на Avito DS Bootcamp.

По событиям внутри суточного окна нужно оценить, относится ли кука к трафику известных сервисов автоматизированного сбора данных.

Целевая переменная:
- `1` — трафик известных сервисов сбора данных;
- `0` — трафик, отнесённый к человеческому.

Для каждой `cookie_id` модель возвращает `score` от 0 до 1.
Чем выше значение, тем вероятнее принадлежность к положительному классу.

В итоговом решении использовал ансамбль трёх LightGBM. Средний Precision при Recall ≥ 70% на трёх временных разбиениях — **0.7664**.

## Данные

Одна строка в `train.csv` и `test.csv` соответствует одной куке с заданным окном наблюдения. Готовых поведенческих признаков нет — их нужно построить по истории событий.

| Файл | Содержание |
|---|---|
| `data/train.csv` | Метаданные куки, границы окна и `target` |
| `data/test.csv` | Метаданные куки и границы окна без `target` |
| `data/events.csv.gz` | История событий для обучающей и тестовой выборок |
| `sample_submission.csv` | Пример формата предсказаний |

События содержат просмотры выдачи и объявлений, листание фотографий, контактные действия, добавление в избранное и другие взаимодействия. Также доступны User-Agent, платформа, характеристики объявлений, поисковые запросы и координаты курсора.

## Подготовка данных и признаки

Сначала проверил дубликаты, пропуски, временные границы и распределения основных полей.

Удалил полные дубликаты исходных событий. Для построения признаков оставил только события внутри окна:

```python
window_start_ts <= event_ts < window_end_ts
```

Названия платформ привёл к общему виду, у поисковых запросов нормализовал регистр и пробелы.
Пропуски не заменял на нули целиком. Отсутствие события может означать нулевой счётчик, а недостаток наблюдений для расчёта статистики — `NaN`. Например, разброс координат по одному наблюдению не определён.
В итоговый набор вошли **337 признаков**: 189 поведенческих и временных и 148 долей конкретных User-Agent.

Основные группы:
- количество и доли разных действий;
- разнообразие объявлений, категорий, локаций и запросов;
- повторные просмотры и концентрация интереса;
- интервалы между событиями, короткие и длинные паузы;
- длительность активности и её распределение по часам окна;
- наличие координат курсора, их разброс и число уникальных значений;
- глубина поисковой выдачи и длины запросов;
- возраст куки;
- доли событий с конкретными User-Agent.

`cookie_id` использую для группировки и формирования ответа. Идентификаторы объявлений в модель напрямую не передаю — по ним считаю агрегаты.

## Что пробовал
Начал с простых моделей и постепенно расширял набор признаков. Сравнил DummyClassifier, RandomForest, LogisticRegression, CatBoost и LightGBM.

Ниже — результаты на одном периоде валидации:
13–16 апреля 2026 года. Обучение выполнялось на данных до 13 апреля.

| Вариант | P@R≥0.7 |
|---|---:|
| Константный baseline | 0.0773 |
| RandomForest на двух признаках активности | 0.1000 |
| LogisticRegression на 23 базовых признаках | 0.1993 |
| CatBoost на 23 базовых признаках | 0.1951 |
| CatBoost с временными признаками | 0.3107 |
| CatBoost с разнообразием просмотров и поиска | 0.3937 |
| CatBoost с расширенными временными признаками | 0.4183 |
| LightGBM на расширенном наборе из 189 признаков | 0.6932 |
| Итоговый ансамбль LightGBM на 337 признаках | 0.7373 |

В ходе исследования менял и признаки, и параметры моделей. Поэтому таблица сравнивает варианты целиком: весь прирост нельзя приписать одной группе признаков.

Отдельно проверил обобщённые признаки User-Agent, повторяемость координат, переходы между событиями, сессии с разными границами и короткие всплески активности. Не все дополнения давали устойчивый прирост на разных периодах.

Также попробовал несколько seed для CatBoost и усреднение предсказаний LightGBM и CatBoost. Усреднение оценок оказалось лучше усреднения рангов.

Подробные эксперименты и промежуточные результаты оставил в `research.ipynb`.

## Итоговая модель

Выбрал три LightGBM на одном наборе признаков. Во всех моделях установил `scale_pos_weight=3`.

| Модель | `colsample_bytree` | `min_child_samples` |
|---|---:|---:|
| 1 | 0.85 | 30 |
| 2 | 0.70 | 30 |
| 3 | 0.85 | 15 |

Остальные основные параметры общие:
`learning_rate=0.035`, `num_leaves=31`, `reg_lambda=1`.

Предсказания усредняю с равными весами. При валидации использую раннюю остановку по binary logloss. Число деревьев для обучения на всём train выбираю по медиане лучших итераций на временных разбиениях.

## Валидация и результаты

Тестовые окна расположены позже обучающих, поэтому выбрал последовательные временные разбиения с расширением обучающей выборки.

В обучение включаю только куки, окна которых завершились к началу валидации.

| Обучение | Валидация | P@R≥0.7 |
|---|---|---:|
| 6–9 апреля | 10–12 апреля | 0.7619 |
| 6–12 апреля | 13–16 апреля | 0.7373 |
| 6–16 апреля | 17–19 апреля | 0.8000 |
| **Среднее** | | **0.7664** |

Все даты относятся к 2026 году.
Минимальное значение по трём периодам — **0.7373**.

Основную метрику считаю функцией из `metric.py`, приложенного к заданию. Она выбирает максимальный Precision среди порогов, при которых Recall не ниже 70%. Куки с одинаковым `score` обрабатываются одной группой.

Все три периода использовал при выборе решения, поэтому это результаты локальной валидации, а не независимая оценка на скрытом тесте.

## Как запустить

Использовал **Python 3.12.11**.
В экспериментах и итоговой модели зафиксировал seed **42**.

1. Установить зависимости в выбранное окружение:

   ```bash
   python -m pip install -r requirements.txt
   ```

2. Положить `train.csv`, `test.csv` и `events.csv.gz` в папку `data`
   в корне проекта. Ноутбук также поддерживает несжатый `events.csv`
   и расположение данных рядом с ноутбуком.

3. Убедиться, что `metric.py` находится рядом с ноутбуком.

4. Открыть `final_solution.ipynb` в Jupyter или VS Code,
   выбрать подготовленное окружение и выполнить все ячейки сверху вниз.
   Рабочий каталог — корень проекта.

Запускать исследовательский ноутбук перед итоговым не требуется.

После выполнения появится `submission.csv` с двумя колонками:

- `cookie_id` — идентификатор из `test.csv`;
- `score` — оценка модели от 0 до 1.

Для каждой тестовой куки сохраняется одна строка.
Порог классификации в файл не записывается.

- Положительный класс представлен известными сервисами сбора данных. Качество на других типах ботов отдельно не проверял.

- У куки с короткой историей меньше информации для расчёта временных и других статистических признаков.

Итоговый score использую для ранжирования.
Калибровку вероятностей отдельно не проводил.
